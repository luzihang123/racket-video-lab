# Web 产品与项目结构

> 状态：目标设计。仓库目前只有文档与正手证据样例，尚无可运行的 Web、API 或分析程序。目录和接口按用例逐步落地，不预建空模块。

## 产品边界

RacketLab Web 是训练视频的主工作台：导入一段训练录像，等待后台分析，沿时间轴查看不同动作片段，复核每条观察对应的画面，并记录下一次训练要练的重点。首个运动项目是网球，但导航、片段与证据模型不以“正手”为顶层概念。正手只是最先验证的分析模块；反手、发球、截击、步法等模块按实测结果逐步加入。

Web 展示后端实际提供的能力。动作可处于“可自动定位”“可分析”“仅可人工标注”等不同阶段；界面从能力清单读取状态，不把尚未实现的动作诊断展示成可用功能。

## 页面与主流程

| 路由 | 页面 | 核心任务 |
| --- | --- | --- |
| `/sessions` | 训练记录 | 创建训练、查看视频与分析状态、继续上次复盘。 |
| `/sessions/:sessionId` | 训练详情 | 导入视频、查看拍摄信息与任务进度、进入动作复盘。 |
| `/sessions/:sessionId/review`、`/sessions/:sessionId/review/:segmentId` | 动作复盘 | 视频和动作时间轴联动；按类型筛选片段；确认、排除或改标候选；查看短片、关键帧、观察和无法判断的原因。 |

主流程为：**创建训练 → 导入视频 → 异步分析 → 浏览候选动作 → 逐条复核证据 → 保存训练重点**。桌面布局以视频和时间轴为中心，证据在侧栏；窄屏按“视频 → 片段列表 → 证据”纵向排列。片段应有可分享的稳定地址，便于稍后回到同一次动作。

第一阶段只保证已验证的正手候选和证据可用。其他动作在有可靠检测或人工标注能力前，不凭空出现在时间轴中。训练对比、教练协作和更多运动项目属于后续页面，不占用初版导航。

## 前端目录

选择 React + TypeScript + Vite 的单页应用；[Vite 官方指南](https://vite.dev/guide/)提供 `react-ts` 模板。按用户任务组织 `features/`，避免每个页面各写一套视频、片段和证据逻辑。

```text
web/
├── package.json
├── tsconfig.json
├── vite.config.ts
├── index.html
├── public/                      公开静态资源，不放用户视频
├── src/
│   ├── main.tsx                  浏览器入口
│   ├── app/
│   │   ├── App.tsx               应用外壳与错误边界
│   │   └── routes.tsx            页面路由
│   ├── pages/
│   │   ├── SessionsPage.tsx
│   │   ├── SessionDetailPage.tsx
│   │   └── ReviewPage.tsx
│   ├── features/
│   │   ├── sessions/             训练记录与拍摄信息
│   │   ├── video-import/         上传、校验、失败恢复
│   │   ├── analysis-jobs/        任务阶段、进度、重试
│   │   ├── action-segments/      时间轴、分类筛选、人工改标
│   │   ├── evidence-review/      短片、关键帧、观察、复核决定
│   │   └── training-focus/       本次训练重点
│   └── shared/
│       ├── api/                  HTTP 客户端、OpenAPI 类型
│       ├── ui/                   通用组件
│       ├── media/                视频播放器和时间码工具
│       └── styles/               全局样式与设计变量
└── tests/                       关键交互和时间轴逻辑
```

`pages/` 只组合功能模块；`features/` 管各自的查询、交互与局部状态；`shared/` 不包含网球规则。动作名称、支持状态、观察维度由 API 返回，不在组件中写死“正手五阶段”。后端 FastAPI 的 OpenAPI 文档作为请求与响应类型的来源，生成或校验前端类型，避免两套模型漂移。

## 通用数据契约

| 对象 | 最小字段与职责 |
| --- | --- |
| `Session` | 训练日期、标题、场地或机位备注，以及关联视频。 |
| `Video` | 文件元数据、时长、帧率、尺寸、导入状态；原片留在服务端数据目录。 |
| `AnalysisRun` | 任务状态、阶段、进度、错误、分析版本和模型版本。 |
| `ActionSegment` | 视频 ID、起止时间、运动项目、可为空的动作类型、分类来源与置信度；独立记录分析状态和人工复核状态。 |
| `Observation` | 对某片段的具体观察、可读解释、置信度、证据引用；无法判断时给出原因。 |
| `EvidenceAsset` | 指向短片或关键帧的媒体 ID、时间点、阶段名称与媒体类型。 |
| `ReviewDecision` | 用户对候选片段的确认、排除或改标，保留原自动结果。 |
| `TrainingFocus` | 用户为本次训练选定的一个改进重点及其关联观察。 |

`ActionSegment` 是视频时间轴的通用单位，既可表示正手、反手、发球等击球动作，也可表示步法等非击球动作。自动分类不确定时保留为“待分类”；分析未支持、证据不足和任务失败是不同状态。观察必须能回到具体时间和媒体证据。未标定的单机位视频不输出未经验证的厘米级测量；现有正手 [样例数据](../examples/forehand-groundstroke/evidence.json) 中的精确数值只作历史演示，不能直接当作生产输出契约。

## HTTP 边界

建议让 Web 与 API 共用 `/api/v1` 契约。下表是规划入口，最终路径以实现时的 OpenAPI 为准。

| 入口 | 用途 |
| --- | --- |
| `GET/POST /sessions`，`GET /sessions/{id}` | 训练记录列表、创建和详情。 |
| `POST /videos` | 导入视频并关联训练；大文件需要可恢复的上传流程。 |
| `POST /analyses`，`GET /analyses/{id}` | 提交分析、轮询状态；API 立即返回任务 ID。 |
| `GET /analyses/{id}/segments` | 时间轴数据与动作类型筛选。 |
| `GET /segments/{id}`，`POST /segments/{id}/reviews` | 片段详情及人工确认、排除、改标；复核作为独立记录保存。 |
| `GET /segments/{id}/evidence` | 观察、关键帧、短片与无法判断的原因。 |
| `GET/PUT /sessions/{id}/focus` | 查看或保存本次训练重点。 |
| `GET /capabilities` | 当前运动项目、动作类型及检测/分析/人工标注能力。 |
| `GET /media/{assetId}` | 受控读取原片、短片或关键帧。 |

网页不直接拼接服务器文件路径。媒体入口通过 ID 查找授权资源；视频播放应支持 HTTP Range，以便拖动和逐帧定位。[Starlette 的 `FileResponse` 文档](https://www.starlette.io/responses/)说明其 Range 行为。长视频上传需显示进度并能从中断处恢复，上传完成后才创建分析任务；不要让浏览器请求一直等待模型运行。

## 开发与部署

- 本地开发：`web/` 的 Vite 开发服务器将 `/api` 与媒体请求代理到 FastAPI；前端只使用相对路径。API 和 worker 分进程运行。
- Mac mini 部署：构建 `web/dist/` 后由 FastAPI 提供前端静态资源与单页路由回退；`/api` 和媒体路由保持优先。FastAPI 支持挂载静态文件，见[官方文档](https://fastapi.tiangolo.com/tutorial/static-files/)；实际路由回退需在应用中实现和验证。
- 视频、证据、数据库和模型继续放在仓库外的 `RACKETLAB_DATA_DIR`，不进入 `web/public/` 或 Git。默认仅本机访问；开放局域网访问前补齐身份验证、访问控制和传输保护。

## 落地顺序

1. 建训练、视频、分析任务的后端契约和 Web 外壳，完成导入与进度页。
2. 用正手真实样例接通通用动作时间轴、证据页和人工复核；检验找片段与复核是否省时。
3. 接入新的网球动作模块时扩展能力清单和分析适配器，复用现有页面。
4. 有两次以上可比训练记录后，再建设训练趋势和教练协作。

关键验收：用户能从长视频定位到一次动作，回看每条观察的证据，纠正误判，并清楚知道哪些动作或结论尚不受支持。
